O que é o Claude Code

Claude Code é a CLI oficial da Anthropic que traz o Claude diretamente para o seu terminal. Ele entende o contexto do seu projeto, lê arquivos, executa comandos, cria commits e auxilia em tarefas de engenharia de software — tudo sem sair do terminal.

Interativo

Converse em linguagem natural para editar código, criar arquivos e rodar testes.

Contextual

Lê o repositório inteiro, entende a arquitetura e sugere mudanças consistentes.

Extensível

Suporta hooks, servidores MCP, comandos customizados e integrações via SDK.

⚡

Instalação rápida

  1. Certifique-se de ter Node.js 18+ instalado.
  2. Instale globalmente via npm: npm install -g @anthropic-ai/claude-code
  3. Abra um terminal na raiz do seu projeto e execute claude.
  4. Na primeira execução, faça login com sua conta Anthropic.
  5. Rode /init para que o Claude gere o arquivo CLAUDE.md do seu projeto.
💡
Use claude --version para confirmar a instalação e claude --help para ver todas as opções da CLI.
📁

Estrutura de pastas

O Claude Code usa dois escopos de configuração: global (vale para todos os projetos) e projeto (versionado junto com o repositório).

~/.claude/ # configurações globais (usuário) ├── settings.json # permissões, hooks e preferências globais ├── CLAUDE.md # instruções pessoais que valem em todo projeto └── commands/ # comandos slash globais customizados └── meu-comando.md seu-projeto/ # raiz do repositório ├── CLAUDE.md # instruções do projeto (commitado) ├── .claude/ # config específica do projeto │ ├── settings.json # permissões e hooks do projeto │ ├── settings.local.json # config local (não commitar — add ao .gitignore) │ └── commands/ # comandos slash do projeto │ └── deploy.md └── ... (código do projeto)
⚠️
Adicione .claude/settings.local.json ao seu .gitignore. Esse arquivo pode conter tokens e preferências pessoais que não devem ser versionados.

Hierarquia de configurações

As configurações são mescladas nesta ordem de prioridade (maior sobrescreve menor):

1º settings.local.json

Maior prioridade. Config pessoal e local, não versionada.

2º .claude/settings.json

Config do projeto, versionada no repositório.

3º ~/.claude/settings.json

Menor prioridade. Defaults globais do usuário.

📄

O arquivo CLAUDE.md

É o arquivo mais importante do projeto. Funciona como um "briefing" permanente — o Claude lê esse arquivo em toda sessão antes de responder qualquer coisa. Pense nele como o contrato entre você e o assistente.

ℹ️
Execute /init para gerar automaticamente um CLAUDE.md baseado no código existente. Depois edite conforme necessário.

O que colocar no CLAUDE.md

Comandos essenciais

Como rodar testes, build e linter. Ex: npm test, make build.

Arquitetura

Visão geral dos módulos, camadas, padrões de design usados.

Convenções

Estilo de código, naming, idioma dos commits, estrutura de PRs.

Restrições

O que o Claude não deve fazer. Ex: não alterar arquivos de config de produção.

Exemplo de CLAUDE.md

CLAUDE.md
# Projeto: API de Pagamentos

## Comandos
- Rodar testes: `npm test`
- Build: `npm run build`
- Lint: `npm run lint`
- Dev server: `npm run dev`

## Arquitetura
- API REST com Express + TypeScript
- Camadas: controllers → services → repositories
- Banco de dados: PostgreSQL via Prisma ORM
- Autenticação: JWT com refresh tokens

## Convenções
- Commits em inglês, estilo Conventional Commits
- Nomes de funções em camelCase, tipos em PascalCase
- Testes: um arquivo `.spec.ts` por módulo
- Sem comentários óbvios no código — só WHY, nunca WHAT

## Restrições
- Não alterar arquivos em `infra/` sem aprovação
- Não commitar credenciais ou segredos
- Sempre rodar `npm test` antes de concluir uma tarefa

CLAUDE.md em subpastas

Você pode criar arquivos CLAUDE.md em subdiretórios. Eles são lidos quando o Claude acessa arquivos dentro daquela pasta — útil para módulos com regras específicas.

⚙️

settings.json

Controla permissões, hooks e comportamentos automáticos. Pode existir em nível global (~/.claude/) e por projeto (.claude/).

Estrutura básica

.claude/settings.json
{
  "permissions": {
    "allow": [
      "Bash(npm run *)",        // permite npm scripts
      "Bash(git status)",        // comando específico
      "Read(**)",                // leitura de qualquer arquivo
      "Write(src/**)"            // escrita só em src/
    ],
    "deny": [
      "Bash(rm -rf *)",           // bloqueia deleção recursiva
      "Write(.env*)"             // protege arquivos de ambiente
    ]
  },
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write",
        "hooks": [{ "type": "command", "command": "npm run lint --silent" }]
      }
    ]
  }
}

Padrões de permissão

PadrãoSignificado
Bash(npm *)Permite qualquer comando npm
Bash(git status)Permite somente git status
Read(src/**)Leitura de qualquer arquivo dentro de src/
Write(*.md)Escrita apenas em arquivos Markdown
mcp__github__*Permite todas as ferramentas do MCP GitHub

Comandos slash

Digite / seguido do comando durante qualquer sessão para acessar ações especiais.

Comandos essenciais

ComandoO que fazDica
/help Lista todos os comandos disponíveis básico
/init Gera o CLAUDE.md baseado no projeto atual início
/clear Limpa o contexto da conversa atual básico
/compact Comprime o histórico para liberar contexto sessões longas
/config Abre o menu de configurações (tema, modelo, etc.) básico
/review Revisa o diff atual da branch em busca de bugs qualidade
/doctor Verifica saúde da instalação e configuração debug
/status Mostra status do projeto e configurações ativas básico
/memory Edita o CLAUDE.md do projeto ou global avançado
/bug Reporta um bug do Claude Code no GitHub suporte

Opções de linha de comando (CLI)

claude                           # abre sessão interativa
claude -p "corrija os testes"      # executa prompt e sai (non-interactive)
claude --continue                 # retoma a última conversa
claude --resume                   # escolhe sessão anterior para retomar
claude --model claude-opus-4-7    # usa modelo específico
claude --output-format json       # saída em JSON (útil em pipelines)

Modos de permissão

O Claude Code pede confirmação antes de executar ações potencialmente destrutivas. Você escolhe o nível de autonomia.

Default Modo padrão

Pede confirmação para comandos Bash e escrita de arquivos. Ideal para iniciantes.

Auto-approve Aprovação automática

Executa ações pré-aprovadas em settings.json sem perguntar. Use com cuidado.

--dangerously-skip-permissions

Aprova tudo sem perguntar. Somente para ambientes isolados/CI. Nunca use localmente com dados reais.

🚨
Nunca use --dangerously-skip-permissions na sua máquina local com projetos reais. Use apenas em containers Docker ou pipelines de CI isolados.
🪝

Hooks

Hooks são comandos shell que executam automaticamente em resposta a eventos do Claude Code. Permitem automações como rodar o linter após cada edição ou notificar quando uma tarefa termina.

Eventos disponíveis

EventoQuando dispara
PreToolUseAntes de qualquer tool call (pode bloquear a ação)
PostToolUseApós qualquer tool call concluído
NotificationQuando o Claude envia uma notificação ao usuário
StopQuando o Claude termina de responder
SubagentStopQuando um subagente interno termina

Exemplo: linter automático após cada escrita

.claude/settings.json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          {
            "type": "command",
            "command": "npm run lint --silent 2>&1 | head -20"
          }
        ]
      }
    ],
    "Stop": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "echo 'Claude terminou!' | notify-send -"
          }
        ]
      }
    ]
  }
}
⚠️
Hooks executam com seus privilégios de usuário. Revise qualquer hook antes de ativar — eles podem modificar arquivos ou chamar serviços externos.
🔌

MCP Servers

O Model Context Protocol (MCP) permite conectar o Claude a fontes externas de dados e ferramentas: bancos de dados, APIs, sistemas de arquivos remotos e muito mais.

Adicionar um servidor MCP

# Adicionar globalmente
claude mcp add --global meu-servidor node /caminho/para/servidor.js

# Adicionar ao projeto atual
claude mcp add meu-servidor node /caminho/para/servidor.js

# Listar servidores configurados
claude mcp list

# Remover
claude mcp remove meu-servidor

Exemplos de servidores úteis

GitHub MCP

Lê issues, PRs, comentários e arquivos diretamente do GitHub.

Filesystem MCP

Acessa diretórios fora do projeto atual com controle fino de permissões.

PostgreSQL MCP

Executa queries e inspeciona schema do banco diretamente no chat.

Comandos slash customizados

Crie seus próprios comandos /nome salvando arquivos Markdown em .claude/commands/. O conteúdo do arquivo vira o prompt enviado ao Claude.

Estrutura de um comando

.claude/commands/review-pr.md
---
description: Revisa o diff atual buscando bugs e problemas de segurança
---

Revise o diff da branch atual com foco em:

1. Bugs lógicos — condições incorretas, edge cases não tratados
2. Segurança — SQL injection, XSS, exposição de dados sensíveis
3. Performance — N+1 queries, loops desnecessários
4. Cobertura de testes — código novo sem testes

Para cada problema encontrado, informe:
- Arquivo e linha
- Severidade (alta/média/baixa)
- Sugestão de correção

Agora basta digitar /review-pr em qualquer sessão do projeto.

💡
Use $ARGUMENTS no template para passar parâmetros: /deploy staging passa "staging" como $ARGUMENTS.
✅

Dicas essenciais

Contexto e prompts

Seja específico

Em vez de "corrija o bug", diga "o teste users.spec.ts:42 falha porque a validação de email aceita strings vazias — corrija o validador".

Use /compact regularmente

Em sessões longas, rode /compact para comprimir o histórico e preservar tokens para as próximas respostas.

Peça verificação

Após uma mudança complexa, peça: "rode os testes e confirme que tudo passa antes de concluir".

Divida tarefas grandes

Para refatorações grandes, separe em sessões menores e focadas. O Claude trabalha melhor com escopo limitado.

Git e commits

  1. Instrua o Claude a fazer commits atômicos — uma mudança lógica por commit.
  2. Defina o formato de mensagem de commit no CLAUDE.md (ex: Conventional Commits).
  3. Antes de fazer push, peça /review para uma revisão do diff.
  4. Nunca deixe o Claude fazer force push sem confirmação explícita sua.

CLAUDE.md eficiente

💡
Mantenha o CLAUDE.md conciso e sempre atualizado. Um arquivo desatualizado confunde mais do que ajuda. Revise-o toda vez que a arquitetura do projeto mudar.

Segurança

Proteja .env

Adicione "deny": ["Write(.env*)"] no settings.json para bloquear escrita em arquivos de ambiente.

Revise hooks

Antes de ativar um hook, entenda o que o comando faz. Hooks mal escritos podem corromper arquivos.

Confirme ações críticas

Ações como drop de banco, deleção de arquivos ou push forçado devem sempre ter confirmação manual.

🚫

O que evitar

CLAUDE.md vazio ou genérico

Sem contexto do projeto, o Claude não sabe suas convenções e pode gerar código fora do padrão.

Sessões intermináveis

Sessões muito longas acumulam contexto irrelevante. Use /clear ou comece uma nova sessão para tarefas diferentes.

Aprovar tudo sem ler

Leia os diffs antes de confirmar mudanças. O Claude pode editar arquivos inesperados se o escopo não estiver claro.

Commitar settings.local.json

Esse arquivo pode conter tokens pessoais. Garanta que está no .gitignore.

Pedir tudo de uma vez

"Refatore o projeto inteiro" é um prompt ruim. Quebre em tarefas pequenas e verificáveis.

Ignorar os testes

Sempre instrua o Claude a rodar a suíte de testes após mudanças. Código que "parece certo" mas falha em testes não está pronto.
